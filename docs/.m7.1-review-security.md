# P2-M7.1 Task 12 — Security review (2026-07-06)

Scope: the highest-risk / highest-complexity modules for the first private beta —
federation mTLS, envelope encryption + key wrapping, auth (password / signed-URL
/ bearer / upload tokens), secrets handling, SQL-injection surface, container
supply chain. Reviewed inline on the Opus 4.8 orchestrator (Fable subagent budget
exhausted mid-milestone).

## Findings FIXED

1. **Compose runtime images unpinned (supply chain).** `docker-compose.yml`
   pinned postgres/nginx by tag only and `certbot/certbot` by *nothing* (implicit
   `:latest`), inconsistent with the digest-pinned Dockerfile FROMs (Task 5). →
   Digest-pinned all four to manifest-list digests; extended
   `refresh-docker-digests.sh` to the compose file; the `/docker` Dependabot
   ecosystem already watches them so CVE patches still flow via PR.
   Commit e740c06. Severity: Low (self-hosted operator compose, not a published
   artifact) but a stated design-priority gap.

2. **TLS session-resumption footgun latent (federation mTLS).** The two
   `InsecureSkipVerify` + `VerifyPeerCertificate` client configs
   (`CoordinatorClientTLS`, `DonorRepairClientTLS`) are safe *today* — nil
   `ClientSessionCache` means no client resumption, so the custom
   federation-identity check runs every connection. But Go re-runs
   `VerifyPeerCertificate` only on a FULL handshake; a future `ClientSessionCache`
   would silently bypass identity verification on resumed connections. →
   Documented the invariant at both sites + added
   `TestCustomVerifyClientsDisableResumption`. Commit b9b2e84. Severity:
   Low-now / High-if-regressed — hence the regression guard.

## Reviewed and found SOUND (no change)

- **Envelope AEAD (`internal/envelope/v1.go`, `keywrap.go`).**
  XChaCha20-Poly1305 (`chacha20poly1305.NewX`), fresh 24-byte random nonce per
  Seal via `crypto/rand` — extended nonce makes random nonces safe at scale (no
  nonce-reuse birthday bound concern). Master key wraps per-blob keys the same
  way. 32-byte keys enforced. Tag-mismatch returns an opaque error.
- **Password hashing (`internal/auth/password`).** argon2id, t=3, m=64 MiB, p=2,
  32-byte output — sound. Verify rejects degenerate PHC params *before*
  `argon2.IDKey` (which panics on zero), and runs the compare inside a recover
  guard; final compare is constant-time.
- **Signed URLs (`internal/auth/signedurl`).** HMAC compared with
  `subtle.ConstantTimeCompare`; audience + expiry + kid all bound into the
  canonical string; retired-key window honored.
- **Upload tokens (`internal/auth/uploadtoken`).** `subtle.ConstantTimeCompare`.
- **`InsecureSkipVerify` audit.** Exactly two occurrences, both paired with a
  real `VerifyPeerCertificate` (federation-CA chain + `nova://` URI-SAN identity).
  Donor certs carry ClientAuth EKU and NO host SANs by design, so standard
  ServerAuth/hostname verification cannot apply — verification is *replaced*, not
  removed. Byte integrity never rests on TLS (reads re-import + require CID
  equality; audits reconstruct the block CID).
- **Secret logging.** No key/token/password bytes are logged. `keystore.go`
  "master key loaded" logs label + source + active only; the webhook
  secret-file-unreadable warning logs the URL + error, not the secret.
- **SQL-injection surface.** sqlc-generated queries are parameterized. The two
  `fmt.Sprintf`-into-SQL sites are DDL over DB-derived, regex-validated partition
  names (`retention.go`, `^integrity_audits_\d{4}_\d{2}$`) and the bench seeder
  (test-only) — no user input reaches either.
- **Federation listener.** `ServerTLSConfig` = `RequireAndVerifyClientCert`
  against the federation CA, TLS 1.2 floor. Coordinator `/metrics` is
  coordinator-only; donor graph stays prometheus-free (node-deps-check).
