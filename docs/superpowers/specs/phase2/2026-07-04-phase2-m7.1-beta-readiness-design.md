# P2-M7.1 — Beta readiness: deferred-debt closure & release polish (design)

**Date:** 2026-07-04
**Status:** Accepted
**Branch:** `p2-m7.1-beta-readiness`
**Plan:** `docs/superpowers/plans/phase2/2026-07-04-phase2-m7.1-beta-readiness.md`

## Why this milestone exists

Nova's first private beta (QA testers beyond the dev loop) is gated on this
milestone. P2-M7 proved the federation stack operationally; P2-M7.1 closes the
debt that accumulated *around* it: the milestone formerly numbered **M6.1** on
the Phase-2 track is renamed **P2-M7.1** (it runs after M7, and the old name collided with the
Phase-1 M6.1 keystore milestone in casual reference), and its scope is widened
to absorb **every Phase-2 finding/fix that was deferred without already having
a designated future home**. Nothing ships to QA testers with known-broken
production paths, unresolved vulnerability alerts, or docs that misdescribe
the system.

## Scope decisions

### D-M7.1-1 — The rename is total: no reference to the old milestone name survives.

Every occurrence of the old milestone name in docs *and code comments* becomes `P2-M7.1`.
These are all **forward pointers to a future milestone whose identity changed**
— updating them in historical design/plan docs is a pointer fix, not history
rewriting. Historical docs get *only* this pointer fix; their decisions and
narrative are never edited. Known reference sites: `docs/ROADMAP.md` (P2-M7
row), the M7 design + plan docs, `docs/runbooks/donor-lifecycle.md`,
`cmd/novactl/node_drain.go`, `internal/db/queries/drain.sql` (+ generated
`drain.sql.go`, `querier.go` — regenerate via `make sqlc-generate`, never
hand-edit), `internal/audit/possession/verify.go`, `trust_test.go`,
`internal/metrics/collector.go`.

### D-M7.1-2 — Partition maintenance is fixed at three layers (the homeless deferred finding).

The 2026-07-02 finding: `jobs`, `integrity_audits`, and `audit_log` monthly
partitions committed in migrations `0002`/`0003` end at `2026-07-01`. The
runtime `Maintainer` (`internal/audit/integrity/retention.go`) create-aheads
`integrity_audits` + `audit_log` **but not `jobs`** — the `0002` comment
promises "the partition-rotation job" that was never built. Production impact:
**every `jobs` INSERT fails from 2026-07-01** on any instance started before
July whose Maintainer can't help it, and **fresh installs from migrations are
insert-broken for all three tables** in any month ≥ July 2026. Test impact: 9
packages fail on any branch; 2 hang ~15 min (leaked tx on `t.Fatal` blocks
`pool.Close`).

Fix, three layers:
1. **Migration `0017_partition_provisioning.sql`** — a `DO $$` block that
   provisions, for each of the three parents, the *current* month plus 2
   look-ahead months **relative to `now()`**, idempotently
   (`CREATE TABLE IF NOT EXISTS`), using the same naming/bounds convention as
   `retention.go` (`parent_YYYY_MM`, explicit-UTC bounds). Fresh installs work
   in any month forever. Forward-only append; `migrations-frozen` stays green.
2. **Maintainer covers `jobs`** — add `jobs` to the create-ahead loop in
   `maintain()` (no retention/prune pass for `jobs`; the job-queue reaper owns
   row lifecycle). The Maintainer already always runs
   (`pkg/coordinator/coordinator.go` starts it unconditionally).
3. **dbtest harness hang fix** — a failing test must fail fast: `pool.Close`
   must not block forever on a connection leaked by a `t.Fatal`-interrupted
   test body. Bound the close (close in a goroutine with a short grace, or
   restructure acquisition so cleanups release before pool close). Acceptance:
   a deliberately-failing partition-style test exits in seconds, not 15 min.

### D-M7.1-3 — Below-floor bulk re-replication: mirror the drain treatment, ride the healing machinery.

The deferred queue (hysteresis / rate limits / untrusted-replica replacement)
lands as a **sweep + query-classification change**, not a new daemon:

- **Sustained marker with hysteresis.** Migration `0018_below_floor.sql` adds
  `nodes.below_floor_since timestamptz` (NULL = not below floor) + partial
  index. A node *enters* below-floor when `reputation_score <
  reputation_floor` (existing threshold); it *exits* only when
  `reputation_score ≥ reputation_floor + hysteresis_margin` (default
  `0.05`). Replacement only *triggers* once the marker has been set for
  `grace` (default `24h`) — reputation wobble near the floor never flaps
  counts or floods the reconcile queue.
- **Query classification mirrors drain (the M7 pattern).** Safety counts
  (`healthy_acked` / `sourceable_acked` / `CountSourceableHolders`) EXCLUDE
  sustained-below-floor nodes — this is the flip the M7 runbook promised
  ("present-but-untrusted replicas remain countable until the queue lands").
  Placement (`ListPlacementCandidates`) excludes them. Selection
  (`ListSourceableHolders` / `ListRepairSourceHolders`) keeps them,
  deprioritized behind draining nodes in the prepended sort key — an
  untrusted replica is a repair source of *last* resort but never wasted.
- **Rate-limited sweep, lowest healing priority.** The healing tick gains a
  `below_floor` pass that walks **after** `donor_lost` and `tier1`: for each
  sustained-below-floor node, `MarkReplicationDirtyForNode` +
  `EnqueueReconcileForNode(reason='below_floor')`, capped at
  `requeue_batch` (default 500) CIDs per tick across all such nodes. Tier1
  emergencies always outrank replacement of replicas that still exist.
- **Replace, then demote — never a durability dip.** The below-floor replica
  is not invalidated up front; exclusion from safety counts makes healing
  re-replicate onto trusted nodes, and only when the blob's healthy count is
  restored does the sweep fail the untrusted assignment
  (state `failed`, reason `below_floor_replaced`). If the below-floor node is
  the SOLE holder it remains the repair source (same principle as drain's
  self-sourcing).
- **Config block `below_floor_replacement`:** `enabled` (default `true`),
  `hysteresis_margin` (`0.05`), `grace` (`24h`), `requeue_batch` (`500`).
  Two `/settings` knobs: `enabled`, `grace`.
- **Observability:** existing `nova_below_floor_replica_debt` should now trend
  to zero; add scrape-time `nova_below_floor_nodes` + a process-local
  requeue counter through the existing nil-safe observer seams. Donor graph
  stays prometheus-free (`donor-deps-boundary` green; this is all
  coordinator-side).
- **Spec amendments at the owning milestone:** `HEALING_PROTOCOL.md` gains the
  below-floor pass; `docs/runbooks/donor-lifecycle.md` § below-floor debt is
  rewritten from "manual runbook" to "automated with these knobs, here is when
  to intervene anyway".

### D-M7.1-4 — Donor↔donor repair TLS: same fix as the coordinator→donor path, donor-side.

The M7 cross-version drill fixed the coordinator→donor client (federation-CA
chain + `nova://` URI-SAN identity verification,
`internal/federation/transport/identity.go`). The donor's own repair-fetch
client (`internal/node/agent/client.go`) is the same defect class and was
deferred donor-side. M7.1 applies the same verification: chain to the
federation CA, require the expected peer's `nova://` node identity in the URI
SAN, no hostname/ServerAuth fallback. Tested both directions (verifies a
correct donor; rejects a valid-CA-but-wrong-identity server). Donor dependency
boundary unchanged (`transport` is already in the donor graph).

### D-M7.1-5 — Dependency and alert closure follows the standing currency policy.

CONTRIBUTING § Toolchain currency: triage every alert, record the verdict in
the M14 triage-table format, patch unless genuinely breaking. Applied:

- **All 9 open Dependabot vulnerability alerts reach zero-open**: Go
  `golang.org/x/image` (TIFF, high) + `golang.org/x/net` via minor/patch
  bumps; npm `undici` ×5 + `esbuild` via lockfile/transitive bumps.
- **Grouped minor/patch PRs (#13 go, #14 npm)** are absorbed locally (same
  version movements, tests as the gate). Dependabot auto-closes them when
  main is eventually pushed; we do not push.
- **GitHub-Actions major PRs (#1–#5)** are absorbed locally *and* every
  `uses:` is pinned to a full commit SHA with a version comment (closes the
  Scorecard `PinnedDependenciesID` class). `golangci-lint-action` v9 must be
  verified against the v2 `.golangci.yml` + `go-version-file` setup before
  landing; if v9 breaks the lint job contract, stay on v8-SHA-pinned and
  record the verdict.
- **npm major PRs (#7 typescript 6, #9 uppy 5, #10 react-query 5,
  #11 react-router 7)** get individual verdicts: take a major only if the
  full web gate (`make web`) passes with a bounded, mechanical migration;
  otherwise defer with a written verdict and a named home. Majors are not
  release blockers for a beta; broken SPAs are.
- **Docker base images pinned by digest** (`golang`, `node`, `distroless`,
  `debian` bases) with the tag kept as a comment.
- **Workflow token permissions**: top-level least-privilege `permissions:` in
  every workflow; job-level widening only where a job needs it.
- Scorecard checks that require external process changes (CII badge, OSS-Fuzz,
  push cadence, PR-review cadence) get recorded verdicts, not cargo-cult
  fixes.

### D-M7.1-6 — Three review passes, findings in the REVIEW lineage, fixes in-milestone.

Following the `docs/REVIEW_*.md` convention (adversarial audit of as-shipped
code), M7.1 runs three passes and records everything in
**`docs/REVIEW_2026_07_04.md`**, severity-ranked, each finding either fixed
in-milestone (commit referenced) or explicitly deferred with a named home:

- **Security** (highest priority, high-risk modules first):
  `internal/envelope`, `internal/masterkey`, `internal/secret`,
  `internal/auth` (argon2id, local OIDC issuer, refresh tokens), signed-URL
  HMAC path, `internal/federation/{transport,tokens,ca,replay}` (mTLS,
  token mint/verify, replay windows), `internal/api` authz gates + CORS +
  rate limits, metrics-listener exposure, upload pipeline
  (`internal/upload`).
- **Logic/concurrency**: `internal/orchestrator` (liveness/healing/drain
  interplay — including the new below-floor pass), `internal/audit/possession`
  (dispatcher, trust state machine, transactional outcomes), `internal/jobs`
  (leasing, reclaim), lifecycle sweeps; races, lost updates, tx boundaries,
  idempotency, partial failure.
- **Performance**: hot-path queries against the EXPLAIN-gate list, N+1s,
  pool discipline, sweep batch sizes; the 9.8M-row bench artifacts are the
  baseline.

### D-M7.1-7 — Doc truth: drift sweep, deferral-ledger audit, README rebuilt from scratch.

- **Drift sweep** over every *living* markdown file (top-level, `docs/**`
  excluding `docs/superpowers/**` history, `.github`, `deploy`,
  `simulations`): each normative claim is checked against the code; fixes
  land in the doc. Known drift seeds: `docs/images/quickstart/README.md`
  claims the screenshots are uncaptured (they shipped 2026-06-14); dual
  `THREAT_MODEL.md` (top-level vs `docs/specs/`) must be reconciled into one
  canonical + one pointer; README dev-walkthrough claims re-verified.
- **Deferral-ledger audit**: every deferral recorded in a Phase-2 ROADMAP row
  gets a disposition in the REVIEW doc — `shipped-in-<tag>` / `absorbed by
  P2-M7.1` / `moot (reason)` / `re-deferred → <named home>`. Includes the
  Phase-1 stragglers that named Phase 2 as their home (e.g. M10 "cross-node
  rotation propagation → Phase 2", expected moot: donors hold ciphertext
  only, no wrapped DEKs to propagate — verify, then record).
- **README rebuilt from scratch** per D-M7.1-8. The honesty bar for all docs:
  aspirational language is kept (per the standing scale framing) but always
  labeled with where the roadmap actually stands; complex operations
  (key custody, trust model, moderation, drain/decommission) are surfaced,
  never glossed; a new operator or donor can orient without training.

### D-M7.1-8 — README: front-page best practices, honest, visual.

Structure (order is the point — orientation before commitment):
logo/wordmark (extracted as SVG assets from the brand sheet in `docs/design/`
into `docs/images/brand/`, brand red `#B83A18`) → one-paragraph what/why →
badges (CI, CodeQL, Scorecard, license, latest tag — only live, real badges)
→ hero screenshot (setup wizard / admin SPA from `docs/images/quickstart/`)
→ who it's for → feature highlights with per-feature doc links →
architecture diagram + trust-model note (donor-blind, not operator-blind —
kept prominent) → development progress table (Phase 1 ✅ `v0.1.0-rc1`,
Phase 2 federation ✅ through P2-M7.1, next: P2-M8 streaming-AEAD) → three
quickstart paths (operator / donor volunteer / developer) → documentation
map → contributing / security / license. The old README's accurate content
(dev walkthrough, MCP note) moves intact to `docs/` pages rather than
bloating the front page.
